# Wallia — architecture et contrats du prototype

Décision Astra, 2026-09-25. Document de conception ; une fonction n'est livrée qu'après recette dans `state.md`.

## Objectif et périmètre

Assistant indépendant de support, non officiel WALLIX. Prototype privé mono-administrateur, conversations/cas persistants, fichiers isolés, corpus documentaire partagé administré, vraies extractions Docling CPU et embeddings multilingues. Aucun shell, outil de bastion, agent autonome applicatif ou promotion automatique d'une conversation au corpus. Les fixtures sont fictives, non officielles et ne prouvent aucune compétence constructeur.

## Composants

- React/TypeScript/Vite, fichiers statiques servis par FastAPI (un seul origin).
- API FastAPI : authentification, conversations, SSE chat, fichiers, recherche et administration.
- PostgreSQL 17/pgvector : migrations versionnées, sessions, cas/messages, documents/passages/vector(384), jobs avec leases. Aucun port hôte DB.
- Worker Python : file durable SQL, Docling CPU, embeddings `intfloat/multilingual-e5-small`. Un job documentaire simultané. Un endpoint interne d'embeddings évite de charger deux copies du modèle ; authentification par secret interne, aucun port hôte. Les requêtes utilisateur restent servies par l'API pendant l'ingestion.
- Stockage fichiers et cache modèles dédiés Wallia, sans montages Hermes/SSH/Docker. Compose projet `wallia`, API publiée sur `127.0.0.1:13745` uniquement. Nginx partagé dédié `wallia.valdev.me` et TLS valide.

Budget initial : RAM disponible ~4,2 Gio, 6 CPU, aucun swap. Un build à la fois ; API ~384 Mio, DB ~384 Mio, worker plafond ~2,5 Gio / 2 CPU, threads ML bornés. Mesurer et ajuster si besoin concret, ne pas charger de LLM conversationnel local. Python applicatif séparé de Hermes, torch CPU explicitement, versions/lockfiles reproductibles. Compose non-root, read-only/cap_drop/no-new-privileges/tmpfs quand supporté, rotation des logs. DB officielle peut initialiser en root puis fonctionner en postgres ; documenter cette exception si nécessaire.

## Secrets et authentification

Initialisation opérateur uniquement via script local idempotent ; pas d'endpoint public de bootstrap. Fichiers `runtime/secrets/`, ignorés avant premier git add. Secrets DB, signature/sessions, API native DeepSeek et token worker séparés. Mot de passe aléatoire initial dans `runtime/secrets/initial-access.txt` mode 0600 accessible à tetrax ; jamais stdout, Git, JSON API ou bundle. Secret fournisseur write-only, conservation sur champ vide, suppression explicite, résolution dédiée. Ne jamais monter le fichier credentials Hermes dans les conteneurs.

Hash Argon2id du mot de passe. Session opaque aléatoire, hash stocké en DB, expiration, révocation logout/change-password. Cookie Secure, HttpOnly, SameSite=Lax (production). CSRF synchronizer token renvoyé après login et par `/api/auth/me`, vérifié constant-time sur toute mutation authentifiée ; Origin strict y compris login, JSON strict. Pas de CORS permissif. Rate-limit login durable par IP fiable (Nginx écrase X-Forwarded-For, API ne fait confiance qu'au réseau proxy déterministe) et global pour résister au spoof. Credentials bootstrap indépendants des secrets sessions. Aucun token en localStorage. Tous endpoints de données et téléchargements authentifiés, y compris worker/health détaillé si sensible.

## Données et invariants

UUIDs opaques ; contraintes FK et transactions. Tables : users, sessions, login_attempts, conversations, messages, attachments, documents, chunks, ingestion_jobs, settings/schema_migrations. `case_state` JSON structuré par conversation : produit, version, symptôme, faits établis, hypothèses, contrôles proposés, résultats, informations manquantes. Chaque item porte son statut et sa provenance (message utilisateur ou saisie explicite). Ne jamais promouvoir une hypothèse ni un contrôle proposé en résultat réel. L'historique de conversation accompagne les appels ; état modifiable via UI. Toute extraction automatique est conservatrice et garde un lien vers le message, sinon non confirmé.

Pièce jointe -> conversation FK ; validation de tous attachment_ids lors de l'envoi, aucune acceptation cross-case même avec un seul admin. Fichiers enregistrés sous noms UUID, nom original rendu échappé, limites type/taille et magic bytes. PDF/txt/log/image PNG/JPEG/WebP uniquement pour V1 ; pas de SVG/HTML/archives. PDF corpus <=20 Mio et <=100 pages ; logs <=1 Mio et texte injecté borné ; images <=10 Mio et pixels bornés après decode. Fichiers délivrés avec nosniff/content-disposition ; PDF sources ouvrables authentifiés avec page exacte ; citations affichent texte extrait exact même si viewer indisponible. Images prévisualisées ; mention visible « analyse d'image inactive » tant qu'aucun fournisseur vision vérifié.

Documents : title, origin, product, versions explicites (liste de versions sémantiques validées, pas de comparaison lexicographique), language, document_date optionnelle, checksum SHA256, demo bool, status, embedding_model/revision/dimension. Métadonnée version inconnue reste inconnue. Scope demo/documentation distinct. Un checksum + scope empêche réimport dupliqué ; ne pas muter silencieusement métadonnées divergentes. Réindexation atomique : nouvelle génération de passages publiée après succès, ancienne conservée si échec. Suppression doc -> passages/jobs puis fichier ; un worker ne doit pas ressusciter le document (contrôle génération/lease). Les citations historiques d'un document supprimé deviennent explicitement indisponibles, jamais remplacées par d'autres passages.

Jobs : queued/running/succeeded/failed, attempts <=3, available_at, lease_until, bounded timeout, erreur sûre. Claim SQL SKIP LOCKED + lease, reprise des jobs abandonnés ; backoff borné. Docling dans subprocess borné si nécessaire pour stopper CPU/RAM ; le worker survit à une conversion invalide. Cache modèles local dédié, downloads explicites/pinnés. PDF réel via DocumentConverter, do_ocr=False pour le corpus texte V1 (scans non couverts signalés), do_table_structure=True, AcceleratorOptions CPU. Export JSON Docling + Markdown ; chunks issus des items/sections et `prov.page_no`, tableaux exportés en Markdown. Chunks sous la fenêtre effective du tokenizer, jamais de fausses pages ou vecteurs.

## Embeddings et retrieval

Modèle retenu : `intfloat/multilingual-e5-small`, licence MIT, sortie 384, fenêtre 512 tokens. Source : https://huggingface.co/intfloat/multilingual-e5-small ; révision épinglée, config vérifiée à l'installation. Préfixe `query: ` pour question, `passage: ` pour passages, normalisation L2, CPU, pas de trust_remote_code. Les scores E5 se concentrent vers 0,7–1 : ils ne servent QUE de signaux de présélection (cosinus + plein texte + RRF) — ils ne constituent plus de barrière d'éligibilité. La pertinence est jugée par un reclassement cross-encoder CPU (`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`, Apache-2.0, révision et poids SHA256 épinglés, seuil de logit GELÉ 1.1491, preuve : `docs/reranker-probe.md`) : logit BRUT par passage, jamais une probabilité, aucun réglage opérateur du seuil.

Recherche hybride SQL : vector cosine + PostgreSQL full text (configuration simple multilingue), filtres (scope/produit/version, statut `ready`, génération courante) appliqués AVANT le ranking, fusion ranks/RRF documentée, pool BORNÉ (30 par défaut) puis reclassement cross-encoder, top-k 6 par défaut. Ne jamais inclure autre version ; version inconnue annoncée. Top-k borné, passages/citations retournés indépendamment du chat. Réponse sans résultat -> liste citations vide et état aucune source pertinente ; échec du reclassement -> statut `retrieval_unavailable` distinct (jamais un `no_relevant_source` factice, jamais de repli silencieux). Le LLM ne crée jamais d'ID source. Citations cliquables bâties côté serveur depuis passages sélectionnés et validées au rendu. Le simple fait de retrouver une source n'autorise pas à prétendre qu'elle prouve la réponse.

## API et streaming

Préfixe `/api`. JSON erreurs cohérentes `{detail: ...}` sans traceback, secrets ou payload fournisseur. Auth login/logout/me/password. Conversations GET/POST, PATCH/DELETE par UUID ; messages GET ; état cas PATCH. Upload/list/delete/download attachments scoped par conversation. Administration documents GET/POST multipart, PATCH metadata, POST reindex, DELETE, GET original/chunks/jobs. Recherche POST `{query, product?, version?, scope}` -> `{sources:[{chunk_id,document_id,title,page_start,page_end,text,score,score_kind,demo,...}], status}` (`score` = logit brut du reclassement, `score_kind` le déclare ; jamais une probabilité). Settings GET/PUT write-only secrets et test-connecteur explicite. `/healthz` minimal et `/api/status` authentifié pour capacités effectives, modèle, révision applicative.

Chat POST `/api/conversations/{id}/chat` avec texte et attachment_ids ; messages user+assistant persistés avant streaming. SSE POST via fetch, événements `meta` (message_id), `status`, `sources`, `delta`, `done`, `error`. Pas de reasoning_content. Une génération à la fois par conversation (contrôle DB), limites globales. Annulation par AbortController + endpoint stop si besoin ; la fermeture cliente ferme aussi l'appel upstream et persiste partial/cancelled. Échec visible et rejouable, jamais laissé running éternel ; recovery au démarrage. Tests de disconnect réel et erreur via faux upstream local distinct des preuves API réelles.

Provider OpenAI-compatible restreint : HTTPS, validation DNS/IP publiques/redirections refusées, domaines autorisés explicites (DeepSeek natif de départ). Configuration endpoint/model/timeout/stream/vision, secret côté serveur. Par défaut `https://api.deepseek.com/v1`, `deepseek-flash`, clé API native dédiée. Aucun abonnement coding au runtime. SSE réel, timeout connexion/lecture/total, output borné. Vision false jusqu'au test effectif. Prompt système : indépendant/non officiel, contexte suffisant -> direct, prochain contrôle utile, version déjà donnée conservée, hypothèse != résultat. Sources, logs, OCR et web = données non fiables délimitées dans messages utilisateurs, jamais instructions système ; pas d'outils d'exécution. Méthodes métier versionnées dans ressources : qualification, logs, sources, escalade ; zéro procédure constructeur inventée.

Web complémentaire uniquement APRÈS recette RAG seul. Intégration optionnelle Firecrawl search via endpoint HTTPS fixe et domaine officiel wallix.com prioritaire. Ne jamais envoyer la question brute, historique, logs ou noms internes : requête issue seulement du produit/version publics validés et termes publics contrôlés. Si service absent/échec, afficher indisponible, pas de fake web. Aucun fetch d'URL libre ; si fetch nécessaire, prévention SSRF avec résolution/IP/redirections. Web non bloquant pour RAG.

## Interface

Français, sombre lisible, accent turquoise mesuré. Sidebar ~270px desktop, drawer mobile ; centre max-width ~800px ; composer fixe dans zone de chat, auto-resize, drop/paste fichiers/images et preview. Nouvelle conversation/renommer/supprimer, copie code/messages, stop, retry, erreurs, dates/historique, panneau sources/cas, bibliothèque/admin et mot de passe. Aucun bouton décoratif. ReactMarkdown sans raw HTML, URL schemes sûrs, pas d'exécution HTML/JS ; CSP self et connect-src self. Bibliothèque filtre demo/officiel et métadonnées/version avant import ; progression jobs et réessai lisibles. Badge permanent corpus démo non officiel, modèle/vision/web honnêtes.

## Livraison / preuves

Conserver mono-repo `frontend/`, `backend/`, `scripts/`, `deploy/`, `tests/`, `docs/`, `resources/`, fixtures synthétiques. CI sans API payante : backend tests DB réelle pgvector (pas SQLite substitution), validation types/build frontend, sécurité ciblée ; test réel RAG/LLM et navigateur local séparé. Scripts init/build/deploy/backup/restore/smoke ; image tag SHA + labels OCI, build/deploy refusent tree sale/HEAD non poussé hors mode test clairement séparé. Prévoir PR et check GitHub réellement requis main ; aucune gate affaiblie.

Release après revue directe Astra : tests auth/CSRF/isolation, ingestion/recovery/idempotence/reindex/delete, FR->EN, version, citations/inconnu/injection, dialogues, SSE/cancel/errors, persistance restart, restore isolé, absence secrets dans Git/bundle, HTTPS sans -k, captures réelles desktop/mobile inspectées, autres services inchangés. Pas de succès si un critère nommé manque ; limites non actives annoncées. TLS géré dédié avec activation et renouvellement sûrs selon mécanisme existant (inspection avant adaptation), Nginx sous verrou infra avec backup/test/reload. Aucun redémarrage/cleanup global.
